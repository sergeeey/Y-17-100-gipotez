## Как применить `pre_compact` (после резервной копии)

```bash
cp ~/.claude/hooks/pre_compact.py ~/.claude/hooks/pre_compact.py.bak-before-memory-audit
cp tooling-eval/memory-audit-2026-10-14/proposed/pre_compact_patched.py ~/.claude/hooks/pre_compact.py
python tooling-eval/memory-audit-2026-10-14/regress.py     # те же 57 тестов должны дать тот же результат
```

Файл хука установлен ещё и из репо `claude-cod-top-2026-src` (идентичен байт в байт) — патч нужно внести и туда, иначе следующий `--link`-апдейт его перезапишет (в заметке по `post_commit_memory` уже описан такой случай потери правки).

## Риски и границы доказательств

- **E5/E6** проверены одной фикстурой (живой файл «до») и юнит-тестами; на двух внешних корпусах окно тримминга не наступало, поэтому out-of-sample-доказательств по E5/E6 нет.
- **E7**: потолок 12 КБ выбран из условия ограниченного роста, не подбирался по retention; старые сводки переносятся в `history/compacted-<date>.md`, а не теряются, но модель их в сессии не видит.
- **`session_start_digest.diff`** — хук начнёт запускать `digest.py` проекта при старте сессии. Это исполнение файла из репозитория: открытие чужого репо не должно ничего запускать, поэтому патч срабатывает только при наличии маркера `.claude/memory/digest.enabled` (opt-in) и таймаута 15 с. Альтернатива без исполнения кода: пересоздавать `digest.md` в `post_commit_memory` после каждого коммита, а в `session_start` только печатать файл (цена: статус push/публикации обновляется лишь на следующем коммите; в дайджест можно писать `HEAD` и предупреждать при расхождении).
- Эффект доставки (8/8) — симуляция порядка вывода при наблюдаемом 2 КБ-окне харнесса; реальный запуск хука с патчем не делался.
