## Claim 4 -- dim 11 is the maximum; no label > 12: CONFIRMED (and the missing proof is supplied)
* Dimension: Tumarkin's text states <= 11 (primary). My enumeration over all 195 options (all labels <=12, all affine components <=9 nodes) has max d = 11; affine components with 10..15 nodes give no option at all (consistent with "quasi-Lanner order <= 10").
* Labels: a proof for ANY label, not only <=12, replacing the Perron-monotonicity argument. Suppose the base node v is joined to a in A_i by a label m >= 7 (or inf). Pick u_j in each A_j with u_i != a (possible, |A_j|>=2). S' = S minus {u_1,u_2,u_3} contains a and v, |S'| = d >= 4, and must be elliptic or connected parabolic. Affine diagrams have labels only in {3,4,6,inf}, inf only in the 2-node A1~, so S' is elliptic; an elliptic connected diagram with a label >= 7 is the dihedral I2(m), so the component of {a,v} is exactly {a,v}: v has no other neighbour in S'. If v had a neighbour b in A_j, choose u_j != b to keep b -> contradiction; so v has no neighbour in A_j, S is disconnected, impossible for a finite-volume polytope. Hence every v-edge label is <= 6 and the alphabet {3,4,5,6} (plus none) is complete for p=3 (dotted edges are excluded in Lemma 11 because L_i are quasi-Lanner). Edge labels inside A_i are fixed by the affine classification.
* The pair-elliptic prune is valid for every label for the same structural reason: (A_i minus u)+(A_j minus w)+v is a proper subdiagram of S minus {u,w,x}, which is elliptic or connected parabolic; a proper subdiagram of a connected parabolic diagram is elliptic. My run without the prune confirms it empirically.
* Process: the audited decision.md says "a proof for arbitrary labels was not written"; that is accurate.

## Claim 5 -- the 7 strict-geometry polytopes vs Roberts arXiv:1511.08451: REFUTED (discrepancy, unresolved)
* Independent check of the 7: from the 1803 stored c2k2 matrices my own pipeline accepts exactly 7 (1796 rejected for spacelike rays, same as the audit), 7 distinct iso classes, all Euler = 1. Vertex data (degree = number of facets through a vertex):
  d=3 (6 facets): 3 non-simple vertices (Roberts' appendix covers dims 4..10 only, d=3 not comparable; Andreev: infinitely many in H^3);
  d=4 (7 facets), non-simple vertices: [n=7: 0-1:inf 0-6:3 1-5:4 2-3:4 2-6:inf 3-4:4 3-5:3 4-5:4] -> 2; [0-1:inf 0-6:4 1-5:4 2-3:4 2-6:6 3-4:4 4-5:6] -> **1**; [0-1:inf 0-6:4 1-5:4 2-3:4 2-6:6 3-4:4 3-5:3 3-6:3 4-5:6] -> **1**; [0-1:inf 0-6:4 1-5:inf 2-3:4 2-6:4 3-4:4 4-5:inf] -> 3; [0-1:inf 0-6:3 1-5:inf 2-3:3 2-6:6 3-4:6 4-5:inf] -> 3; [0-1:inf 0-6:4 1-5:inf 2-3:3 2-6:6 3-4:6 4-5:4] -> 2. None is a pyramid (max degree 5 < d+2 = 6).
* Roberts' scope = non-compact, non-pyramidal, n+3 facets, exactly one non-simple vertex. The two d=4 polytopes with exactly one non-simple vertex are therefore in scope. I read the TikZ source of Roberts' whole dim-4 appendix (sec. 7.1, both chunks): EVERY subfigure contains at least one dashed edge (labelled cosh, i.e. a pair of ultraparallel facets). The two polytopes have no dotted edge (all facets pairwise meet or are parallel). So they are absent from Roberts' list. The other four have >=2 non-simple vertices, outside Roberts' scope and outside Tumarkin's pyramid lists: no published list I can read covers them.
* Interpretation: either Roberts' appendix is incomplete for polytopes with mutually intersecting facets, or a definition mismatch I cannot see, or a shared flaw in the (standard) Vinberg/cone validators. My independent re-implementation (different code, Qhull instead of subset-SVD) agrees with the audited one on all 7, so the audited toolkit is not the likely culprit, but both rely on the same mathematics. To be checked with CoxIter and/or by asking Roberts/Tumarkin before any statement. NOT a LEAD claim (K3 needs a verified absence from all lists), but decision.md's "ALREADY_KNOWN" is not supported for the k=2 family, and its sentence "no diagram-level comparison was possible" is wrong: Roberts' diagrams are available as TikZ text in the arXiv source (readable through get_paper_latex_section).
